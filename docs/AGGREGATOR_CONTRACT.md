# Aggregator integration contract — D1/D2/D3

Baseline: merged main `24475d4` (PR #11), reviewed on 4 November 2026 IST. The product journey is **register → discover → configure a supported host → authorize/invoke → record → retrieve from another agent**. Engineering is one integration. Original PRD/specification remain historical design inputs; this document changes demo emphasis, not published schemas.

## Existing, usable interfaces

All HTTP paths below are relative to `/api/v1`, require the existing bearer token except health, and use the current API envelope and shared SDK runtime validation. Only the daemon owns SQLite.

| Boundary        | Existing methods / behavior                                                                                                                            | Limitation                                                                                                                                                     |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Inventory       | `listMcpServers`, `getMcpServer`, `createMcpServer`, `replaceMcpServer`, `deleteMcpServer`; GET/POST `/mcp/servers`, GET/PUT/DELETE `/mcp/servers/:id` | Global inventory, **not** project execution authorization. No discovered tools stored.                                                                         |
| State           | `enabled`, status `unknown/healthy/unreachable/disabled`; `checkMcpServerHealth` POST `/mcp/servers/:id/health-check`                                  | Executable `--version` or HTTP reachability probe only. `healthy` does not establish MCP initialize/list/call compatibility.                                   |
| Memory/activity | `getContext`, `listEvents`, `getEvent`, context record/handoff methods; project UUID mandatory in SDK                                                  | Provenance retained; no automatic external tool invocation observations yet.                                                                                   |
| Engineering     | `requestValidation`, `getJob`, `listFindings({jobId})`; approved correction APIs                                                                       | Existing real comparison remains intact. History is distinct from the current job.                                                                             |
| MCP CLI         | `node packages/mcp-gateway/dist/cli.js`                                                                                                                | Five platform tools, no external routing. Use explicit `UDI_PROJECT_ID`, `UDI_DAEMON_URL`, private `UDI_DATA_DIR` to load token. `--url` is currently ignored. |
| MCP tools       | `get_project_context`, `list_project_events`, `get_validation_results`, `record_decision`, `list_available_tools`                                      | The last tool reports inventory/platform capabilities, **not** an external discovered-tool catalog. Decisions retain `agent_summary`.                          |
| Host adapters   | `generateHostConfig`, `previewConfigDiff`, `applyHostConfig` in D2's package                                                                           | Library-only; no host REST routes/SDK methods. Format/safety blockers below.                                                                                   |

Do not add fields to strict existing `McpServerSchema` or `HealthSchema` responses. `capabilities.mcp=true` currently means the old integration is enabled, not that aggregation works. An `AgentRegistrationSchema` type is not a registration/discovery API. Explicit actor labels are not authenticated agent identity.

## Proposed additions — agreement needed, NOT implemented endpoints

D2 should publish its actual schemas/exports first. These names are review candidates, **not** an instruction for D3 to issue requests now. D1 will add reviewed shared schemas/SDK/daemon composition; D2 owns connections, discovery, routing and intelligence. No parallel router or database.

| Capability    | Candidate HTTP / typed SDK                                                                     | Required semantics                                                                                                                                                                                                                                                                                                                                                                            |
| ------------- | ---------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Discover      | POST `/projects/:id/mcp/servers/:serverId/discover`; `discoverMcpTools(projectId, serverId)`   | Review/authorize the registered executable/args or endpoint first; real SDK initialize and tools/list with deadline, cancellation and resource cleanup. Bound catalog/schema size. Store discovery time and connection errors separately from old transport status.                                                                                                                           |
| Catalog       | GET same scope `/tools`; `listMcpTools(projectId, serverId, page)`                             | Stable server/tool identity, input JSON schema, descriptions, last discovery time, explicit unavailable/disabled/stale states. Namespaced identity avoids collisions across servers. Preserve server-provided schemas as data, never execute descriptions.                                                                                                                                    |
| Project grant | Reviewed permission port/endpoint to agree                                                     | Project + server + exact tools, enabled state, argument policy and execution approval. Registering a server or workspace is insufficient. Daemon token identifies the local caller, not a blanket tool grant. No unrestricted shell executor.                                                                                                                                                 |
| Invoke        | POST `/projects/:id/mcp/invocations`; `invokeMcpTool(projectId, input)`                        | Input: serverId, toolName, JSON arguments and agreed authorization reference; optional caller agent/host labels. Check scope/grant/server enabled/tool/schema before execution. Route through D2 gateway, not direct fixture spawn. Return genuine bounded MCP result or explicit failure with invocation ID. Agree synchronous deadline vs durable asynchronous lifecycle before publishing. |
| History       | GET `/projects/:id/mcp/invocations`; scoped detail read; `listMcpInvocations/getMcpInvocation` | Daemon-owned persistence, correlation ID, projectId, serverId, toolName, start/completion UTC, outcome, optional protocol/transport metadata, caller label and redacted summary. Offset/limit rules align with existing lists. Persist success **and** tool/protocol/timeout failures; never turn tool `isError` into success.                                                                |
| Observations  | Reuse existing events/context and MCP reads                                                    | Proposed event `mcp.tool.invocation.completed`, `sourceKind=observed_tool`, actor identifying the gateway, `sourceRef=invocationId`; payload contains identifiers/outcome/redacted summary. Context record links same sourceRef. D2 derives context from real execution. No manually inserted synthetic activity to satisfy acceptance.                                                       |
| Hosts         | Preview/apply port and optional REST methods to agree                                          | Supported hosts enumerable with verified versions/status. Preview exact file/merged changes; explicit approval binds target, reviewed hash and plan. Apply rejects stale/symlink escape targets and preserves backup/unrelated settings. No arbitrary host-file writer.                                                                                                                       |

Use current errors (`UNAUTHORIZED`, `FORBIDDEN`, `VALIDATION_ERROR`, `NOT_FOUND`, `CONFLICT`, `NOT_IMPLEMENTED`, `TIMEOUT`) where appropriate; agree any new mapping instead of silently expanding enums. Generic messages must not expose tokens, credentials, environment variables, entire arguments or raw stderr. Redaction happens **before** persistence and before cross-agent retrieval; summaries should default to tool/outcome, not arbitrary returned text. Define size/truncation limits and test them. Caller-supplied agent/host labels must be identified as unverified metadata.

## Host configuration blockers for D2

The current adapters produce the wrong maps for the targeted files:

- `.vscode/mcp.json`: use `{ "servers": { "udi-platform": { "command": "/absolute/node", "args": ["/absolute/cli.js"] } } }`, not `mcpServers`. See [VS Code configuration destinations](https://code.visualstudio.com/docs/agent-customization/mcp-servers#choose-a-configuration-destination).
- `opencode.json`: use `{ "mcp": { "udi-platform": { "type": "local", "command": ["/absolute/node", "/absolute/cli.js"] } } }`, not `mcp.servers`. See [OpenCode local MCP configuration](https://opencode.ai/docs/mcp-servers/#local).
- Supply `UDI_DAEMON_URL`, explicit `UDI_PROJECT_ID` and private `UDI_DATA_DIR` via the supported host environment field. Let the existing CLI read its private token file; do not inline tokens in generated/shareable config. File-based local token access is not a per-project security boundary.
- `previewConfigDiff` compares lines, not a semantic merge. `applyHostConfig` overwrites the whole object, reuses `.bak`, catches backup/read errors, and does not enforce approval, containment, stale-preview checks or atomic apply. No real user configuration should be applied through this raw API yet. Add a reviewed safe caller/adapter without breaking existing signatures casually. Preserve JSONC/comments where the destination uses them, or fail closed with an actionable message.
- Claude Desktop is an existing unverified generator branch; Antigravity is a desired future target. Neither is verified support. No OpenCode binary is installed on this Mac. Native UDI VS Code extension verification does not prove VS Code's MCP client consumed this generated file.

This branch deliberately leaves D2-owned adapter/aggregator code unchanged. `test:hosts` exposes these issues and writes no personal configuration.

## D3 consumption agreement

Use only `@udi/client-sdk` and `@udi/contracts`. Keep current inventory CRUD operational. Do not ship optimistic “discovered”, “connected”, “executed”, or “authorized” states from registration, transport probes, missing endpoints or locally fabricated history. Disable the corresponding action with a reason until the actual agreed SDK exists. Show observed activity separately from agent summaries; redact before rendering/copying. Scope executions/history to the selected project; discard stale responses after switching projects. Never retry an invocation automatically after a timeout.

D1's next composition boundary is existing `PlatformIntegrations` / `createDefaultIntegrations`. Its MCP port currently exposes only `checkHealth`. Compose D2's reviewed exports there with daemon-owned repositories; external processes continue using the SDK, never SQLite. D2 should also confirm recent activity retrieval beyond the current bounded oldest-first context/event pages; a busy project must not hide its newest invocation. Do not alter frozen paging semantics silently.
